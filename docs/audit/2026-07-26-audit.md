# agora — P(-1) security + correctness audit, 2026-07-26

> **Scope**: agora **1.6.2** (commit `9bdbefd`), audited from a frozen read-only snapshot.
> **Method**: eight dimensions swept in parallel, every candidate finding put to an independent
> skeptic instructed to **refute** it, survivors re-verified against the code before promotion.
> **Result**: **3 HIGH, 5 MEDIUM, 4 LOW, 1 INFO.** No CRITICAL — no path to remote code execution
> or authentication bypass was found anywhere in the audited surface.
> **Disposition — CLOSED**: 3 HIGH + 1 MEDIUM fixed in **1.6.3**, the remaining 4 MEDIUM in **1.6.4**,
> all 4 LOW in **1.6.5**. Every HIGH, MEDIUM and LOW is fixed; the single INFO item is deliberate and
> stays open by choice. Per-finding notes below say what shipped and, where something was declined,
> why. Nothing was carried silently.

The previous audit was [2026-06-15](2026-06-15-audit.md) (at 1.4.4). This one was triggered by the
1.6.x serve-model work: 1.6.0 moved agora from a process per connection to **one process
multiplexing all 64 sessions**, and the guiding question was which assumptions that broke.

## Headline

**Two of the three HIGH findings are reachable with no authentication**, and both are consequences
of the fork→poll shift rather than of new logic:

1. **No send return is checked anywhere in the tree** — 164 call sites, zero tests. On the per-byte
   ingress path that made a slow reader an unbounded resource sink in *both* serve models, and it
   silently disarmed the SO_SNDTIMEO mitigation that the 2026-06-15 audit's **T2** was closed with.
2. **The 1.6.2 arena sweep had reach it did not claim** — `scores` (which needs **no login**), the
   chat live-tail tick (which needs **no input at all**), the connect greeting, and the login path
   were all still on the unreclaimed bump heap; and the arena was sized 256 KB against a worst case
   that is really ~264 KB, so `read` on a large board fell through to the fallback every time.
3. **A bug introduced by 1.6.2 itself** — `descent_write_all`'s EAGAIN retry was a sleepless spin.

The third is the one worth dwelling on: the 1.6.2 cut fixed a class of bug and introduced a fresh
instance of the same class one function away. That is the argument for running the audit *after* a
hardening cut, not before.

## HIGH — fixed in 1.6.3

### H1. Discarded `send_buf` / `echo_byte` returns in the ingress byte loop
**Long-standing** (the poll half arrived with 1.6.0).
`src/main.cyr` — the IAC response drain and the printable-byte echo, both inside `process_rx`'s
per-byte loop.

A tree-wide grep for a tested send return returns **zero hits across ~164 call sites**. Both
primitives report failure correctly — `send_buf` returns 1 on any `n <= 0` (the 1.4.4 **T1** fix)
and `sess_tx_enqueue` returns 1 on an over-cap write *before* copying — and nothing looked.

- **Fork** (Linux default): a client that stops reading fills the socket buffer; every `sys_write`
  then parks for the full `SEND_TIMEOUT_SECS` (60 s) and returns 1; the loop discarded it and moved
  to the **next byte**. One 4096-byte recv could pin a forked child for hours, children are
  unbounded, and the attacker spends nothing after the initial send.
- **Poll**: `sess_tx_enqueue` refuses the write and returns 1 without copying, nobody closes the
  session, and it stays **open but permanently mute** holding 1/64 of capacity — precisely the
  "slow-reader defense" its own comment claims to implement.

**Fixed**: both sites now `store64(quit, 1)` and leave the loop, so `process_rx` returns 1 and both
serve models close the connection, which they already knew how to do.
**Verification honesty**: the fix is by inspection plus no-regression across the full suite. I could
not stage the trigger end-to-end — a non-reading Python client's kernel absorbs enough that the
server never stalls — so the *bug* is argued from the code, not reproduced.

### H2. Poll-mode heap growth still unbounded after the 1.6.2 arena
**New as a miss in 1.6.2**; the mechanism it fails to cover is 1.6.0's.

Four distinct gaps, all on the unreclaimed bump heap under `AGORA_SERVE=poll` (the only model on
agnos):

| Path | Reachability | Measured |
|---|---|---:|
| `scores <game>` → `door_render_leaderboard` / `door_leaderboard_path` | **unauthenticated**, pipelinable | 5,140 B/command |
| `chat_flush_tail` on the idle tick | **no input at all** — a session that sits in a channel | per tick, forever |
| `session_greet`'s MOTD | **unauthenticated**, per accepted connection | 1 KiB/connection |
| login `auth:` buffers | **unauthenticated**, per attempt | per attempt |

Plus the arena's own sizing: `read` allocates its own id-list + post + header buffers (~166 KB) and
then calls `replies_to`, which allocates a **second** id list and post buffer (~98 KB) to scan for
children — ~264 KB against a 256 KB arena, so every `read` on a large board pushed ~15 KB into the
`alloc()` fallback. The 1.6.2 comment claiming the fallback "is not expected to fire in practice"
was simply wrong.

**Fixed**: all nine leaderboard sites and the login/greet/chat-say sites move to `cmd_alloc`
(`scores`: **5,140 → 31 B/command**); the leaderboard's per-row buffer is hoisted out of its loop;
`chat_flush_tail` gets **dedicated process-lifetime statics, not the arena** — the idle tick is not
bracketed by the per-line reset, so routing 49 KB/tick into the arena would only have exhausted it;
and `CMD_ARENA_BYTES` is raised 256 KB → **512 KB** with the sizing note corrected
(`read 1` on a 150-post board: **30,133 → 14,828 B/command**).

**The generalisable lesson**, recorded in `state.md`: *"converted the command arm" is not "converted
the command"*, and a nested call can double a command's footprint without any single function
looking expensive. A grep gate — no bare `alloc()` reachable from `process_rx` — would have caught
both halves and is the obvious follow-up.

### H3. `descent_write_all`'s EAGAIN retry was an unbounded busy-spin
**New in 1.6.2** — introduced by the fix for the poll-mode Descent routing regression.

The client fd is `O_NONBLOCK` in poll mode, so a peer that stops reading returns EAGAIN forever, and
the retry was a bare `continue`: no sleep, no deadline. In poll mode that function runs inside the
process that owns **all 64 sessions**, so one wedged Descent player pegs a core and freezes every
other session permanently — nothing else can run to time them out.

**Fixed**: `sleep_ms(20)` between attempts and a 10 s deadline, after which the peer is treated as
dead and the proxy closes. 20 ms matches the poll sweep cadence; 10 s is far longer than a healthy
client needs to drain a 4 KB buffer and far shorter than the 30-minute idle bound.

## MEDIUM

### M1. `account_register` wrote user files without `O_TRUNC` — **fixed in 1.6.3**
Re-registering the **same key** under a shorter handle left the tail of the previous value behind.
Reproduced end to end before the fix: `register --handle averylonghandle` then `register --handle
qix` left `handle` containing `qix\nylonghandle\n`, and `whoami` reported the wrong handle from then
on. Registration is idempotent by design, so overwriting in place is intended — it just has to
overwrite the *whole* file. All three writes now carry `O_TRUNC`; verified the file is exactly
`qix\n` after the same sequence.

### M2. No IAC (0xFF) doubling on any egress path — **fixed in 1.6.4**
A registered user can put raw telnet command bytes into a post Subject or body (`input_byte_ok`
admits 0xFF; the wire path stores verbatim; every render path emits raw), and **every later reader's
client** interprets them — including a bare `IAC SB` with no `SE`, which wedges a conforming client.
There is no removal path short of an operator editing the file.

**1.6.4 took both layers**, on the strength of CLAUDE.md's "the wire is the contract ... any deviation is
a bug, not a feature": a new `send_text` doubles 0xFF and carries the nine stored-content egress sites,
and `input_byte_ok` drops 0xFF at ingress. `send_text` is deliberately separate from `send_buf` — the
latter is the funnel for every byte agora sends *including the telnet layer's own commands*, which must
not be doubled. Verified end to end against a planted post: `before FF FA 18 after` renders as
`before FF FF FA 18 after`, no bare IAC surviving.

### M3. `serve_poll` has no admission control — **fixed in 1.6.4 (scoped)**
64 keepalive connections pin every slot at ~2 bytes/minute each: `IAC NOP` is consumed without a
response and refreshes the idle timer, so the pool fills invisibly and stays full. The fix is a
policy question (absolute session lifetime? per-source-address slot cap? both, and at what numbers?)
rather than a code question, and the numbers belong to the operator.

### M4. `BO_EXCL` is silently dropped on the agnos target — **fixed in 1.6.4**
agnos has no exclusive-create bit, so the hand-rolled `O_WRONLY|O_CREAT|BO_EXCL` opens degrade to a
plain create: `keygen` can overwrite an existing identity seed, and `post_new` can clobber an
existing post file without truncating it. The clean fix is cyrius 6.4.57's `file_create_exclusive`
(which did not exist before the 1.6.1 pin) at both sites, retiring the local `BO_EXCL` enum — the
same shape as 1.6.2's `SYS_MKDIR` removal. **Done in 1.6.4**: both sites use `file_create_exclusive`, the
local `BO_EXCL` enum is deleted, and a second `keygen` against an existing keyfile now refuses and leaves
the key byte-identical (verified).

### M5. `cmd_post` validates `--board` *after* reading `.policy` / `.admins` — **fixed in 1.6.4**
CLI-only and operator-reachable (`--board ../../../../etc`). It re-opens the traversal ordering that
the 0.7.0 audit fixed for `list` / `read`. The fix is to move the existing validation block above the
`board_can_post` call — nothing between them depends on the policy result. Left out of 1.6.3 purely
because it is unrelated to the cut's theme; it is a one-block move and should be the first item of
the next.

## LOW

- **L1. `board_path` has no bound on the operator's `--store`** — **fixed in 1.6.5**. Bounded at the two
  parse points (`cmd_serve`'s own, and `parse_store`, which serves every CLI verb) rather than at ~30
  builders. Over-long **refuses** rather than truncating — a silently shortened store root would point at
  a different directory. Verified: exit 2 with a clear message, normal paths unaffected.
- **L2. Wire-side Subject and body bypass the CLI's control-byte filter** — **fixed in 1.6.5**.
  `input_byte_ok` now drops the C0 set and DEL (TAB/CR/LF stay — CR/LF are load-bearing, since this
  filter runs *before* EOL detection). The Subject also gets `header_text_buf_ok`, though that branch is
  belt-and-braces: verified, the ingress filter already strips the bytes before the Subject is captured,
  so it does not fire today. It stays to state the header contract if the ingress filter is ever
  loosened. Verified: `a<BEL>b<BS>c<DEL>d` stores as `abcd`. Updating this behavior moved a passing
  test — see the INFO item, which predicted exactly that.
- **L3. Echo is never suppressed after a client revokes ECHO** — **fixed in 1.6.5**, gated on
  `!= Q_NO` exactly as sketched. The `== Q_YES` trap was real and is now pinned in both directions by
  `27-audit-lows.py`: echo survives for a client that never negotiates (netcat shape, and every one of
  agora's own smokes), and stops after a genuine `IAC DONT ECHO`.
- **L4. Bytes pipelined behind `descent` are lost, then executed as BBS commands** — **fixed in 1.6.5**.
  `process_rx` publishes the remainder of the recv buffer before each dispatch; `descent_run` claims it
  and forwards it to the MUD before the shuttle starts, and a claimed tail is not re-executed. Verified
  against a fake MUD under both serve models: the pre-1.6.5 binary loses `north`, this one delivers it.

## INFO

- **BS / DEL are not edited out** for clients that never negotiate LINEMODE (e.g. `telnet host 2323`,
  where BSD telnet suppresses its own option salvo on a non-23 port). Deliberate and recorded, not a
  defect; picking it up as roadmap polish would change a passing test.
  **Update (1.6.5)**: L2 now *drops* BS and DEL rather than storing them, so they no longer reach other
  readers — but they still do not **edit the line**, which is what this item is about. The prediction
  held exactly: fixing the storage half moved `t32`, whose old assertion had conflated the two.

## What this audit did not cover

- **No dynamic analysis.** Everything here is source-level. No fuzzing of the IAC state machine
  (`cyrius fuzz` harnesses do not exist for agora yet), no sanitizer run, no timing analysis of the
  crypto path.
- **The vendored stdlib was read, not audited.** `lib/*.cyr` was consulted for real signatures and
  semantics; its own correctness is cyrius's audit surface, not agora's. The one stdlib issue named
  here (`dir_list`'s per-call allocation) is a performance property, not a vulnerability.
- **agnos paths are reasoned, not run.** M4 and the agnos branches of the 1.6.2 syscall work were
  verified against the syscall tables and the kernel ABI docs; no agnos runtime was exercised.
- **No multi-user race testing beyond the existing concurrency smokes.** The flock'd world
  transaction was read for lock discipline; 8-process and 6-process smokes exercise it, but no
  adversarial interleaving was constructed.
- **The 1.6.3 changes in this document were audited as 1.6.2** — the snapshot predates them. The
  fixes are covered by the test suite and the smokes, not by this audit pass.

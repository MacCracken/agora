# agora — release security pass, 2026-10-12 (1.8.0)

> **Scope**: the 1.8.0 cut — cyrius **6.6.2 → 6.7.9**, darshana **0.9.0 → 1.3.0** — and the CLAUDE.md
> § Security Hardening minimum over the surface those two moves touch: every path by which **stored or
> other-user text reaches a terminal**, the `_buf` composer call sites, and the signal-mask handling
> across fork. Not a full P(-1) (no external CVE research, no benchmark-driven sweep).
> **Result**: **1 MEDIUM, 2 LOW, 4 INFO.** No CRITICAL or HIGH.
> **Disposition — CLOSED in 1.8.0**: the MEDIUM and both LOWs are fixed; the INFO items are recorded
> results, not defects.

The previous audit was [2026-07-26](2026-07-26-audit.md) (1.6.2, closed at 1.6.5).

## MEDIUM — fixed in 1.8.0

### M1. Stored text carried live terminal control sequences to every reader
**Long-standing** — present since posts became readable over the wire (M5), narrowed but not closed by
M5-H (ESC/NUL at ingress) and 1.6.5 (rest of C0 + DEL at ingress).
`src/main.cyr` `send_text` (and every caller), `cmd_read` / `cmd_list`; `src/board.cyr` `input_byte_ok`,
`header_text_ok`.

agora filtered **ingress**, per byte, and `send_text` only doubled IAC. What got through:

- **C1 controls over the wire.** `input_byte_ok` passes 0x80–0xFE so UTF-8 can be posted, and that range
  is also the C1 set — raw (0x9B = CSI, 0x9D = OSC, 0x9C = ST) and UTF-8-encoded (`C2 9B` = U+009B,
  a CSI to any terminal that honours C1 controls). Subjects (`header_text_ok`) likewise.
- **Anything the CLI stored.** `agora post` writes its stdin body with no filter at all, ESC included.
  (The comment on `input_byte_ok` said the CLI refused these bytes; only `--subject` is checked.) The
  same holds for pre-filter posts and hand-edited files.
- **The operator's terminal.** `agora read` / `agora list` printed stored fields raw to stdout.

**Repro (1.7.1 binary, both serve models)** — `docs/examples/29-egress-sanitize.py` with
`AGORA_BIN=<1.7.1 build>`: as registered `qix`, post subject `subj C2 9B 31m red` and a body including
`c1 csi: C2 9B 2J`, `osc52: C2 9D 52;c;cHduZWQ= C2 9C`, `raw c1: 9B 31m`; separately `agora post` a body
`cli ESC[2Jesc BEL bel`. An **anonymous** second session's `read` received all of those bytes verbatim
(`Subject: subj \xc2\x9b31m red`, `cli \x1b[2Jesc\x07bel`), as did `list` and `agora read` — **44
failed checks**. Effect on a terminal that acts on the sequence: screen clear / recolour / cursor moves,
window-title set, and on terminals that honour OSC 52 a clipboard write. Preconditions: the wire half
needs a registered account (the default `anon-read, auth-post` policy) and a C1-honouring reader
terminal; the CLI half needs local store access and works on every terminal.

**Fixed** ([ADR 0024](../adr/0024-egress-text-sanitization.md)): `send_text` and a new stdout twin
`write_text` neutralize every chunk with darshana's `tty_sanitize_buf` in UTF-8 mode, keeping TAB / CR /
LF, before the IAC pass. Every control byte or sequence becomes one `?`; well-formed UTF-8 is unchanged;
the stored post is not rewritten. The same smoke is green on 1.8.0 under both serve models; unit tests
t223–t225 pin the rule, the chunking (byte-identical to one-shot, over every cap 4–12 and 504) and the
IAC pass. Mutation-checked: dropping the UTF-8 boundary rule, CR from the keep set, or switching to
Latin-1 mode each turns the suite red.

## LOW — fixed in 1.8.0

### L1. Leaderboard rows copied into a 320-byte buffer with no bound
`src/main.cyr` `door_render_leaderboard`. Each row of the shared leaderboard file was copied byte by
byte into `cmd_alloc(320)` with no length check; a row over ~314 bytes overran the arena allocation.
agora's own rows are ~50 bytes (`door_format_score`: a validated handle, a score, a rank string), so
reaching it needs a damaged or hand-edited leaderboard — but `scores` is reachable unauthenticated.
**Fixed**: the copy is clamped to `LB_ROW_CAP - 2` so the CR LF always fits; a valid row is
byte-identical. The row now also leaves through `send_text`.

### L2. `boards` sent directory names read off the disk raw
`src/main.cyr` `session_execute` § boards. `boards_list` keeps any non-dot directory under the store;
only names created through `enter` are known to pass `board_name_valid`. An operator-created directory
name reached every client verbatim — no IAC doubling, no sanitization (the roadmap's "the one
content-ish string still reaching the wire without `send_text`"). **Fixed**: routed through `send_text`.
A valid name is byte-identical.

## INFO — recorded results

### I1. darshana `_buf` composer -1 audit (0.9.3 change)
darshana 0.9.3 made the `_buf` composers return -1 for a negative `pos`. agora's call sites:
`render_motd` (two `tty_sgr_buf`, two `tty_sgr_reset_buf`) and, since 1.8.0, `emit_sgr`. None can
produce -1: `render_motd`'s `pos` starts at 2 and only grows, and its codes are the in-range
`TTY_FG_CYAN` / `TTY_FG_YELLOW`; `emit_sgr` composes at offset 0 of a stack scratch and checks the
return. Hardened anyway: `motd_emit_cstr` now passes a negative `pos` through without writing, so the
whole MOTD chain is -1-poisoning like darshana's and a -1 yields an empty MOTD, never a write below the
buffer. MOTD bytes are unchanged (A/B against the 1.7.1 build: 3,750-byte session transcripts identical).

### I2. Signal mask across fork — children are not left with a blocked EXIT mask
agora never called darshana's `tty_open_signalfd` (its N1 shutdown signalfd is hand-rolled, for the
agnos/mirshi rule that a blocked signal is never delivered through a signalfd there), so darshana's
0.9.3 / 1.0.2 signalfd fixes do not reach it; its own failure path already unblocked and returned -1.
darshana 1.1.4's hazard — a signalfd's block is inherited across fork **and** execve — is handled by
`shutdown_signals_child_reset`, the first call in every fork child (closes the inherited signalfd,
unblocks INT|TERM). agora has **no exec / spawn anywhere** (doors are in-process modules; Descent is a
TCP connect). Smoke 28 re-run on 1.8.0: the fork child's `SigBlk` is clear and it dies on SIGTERM.

### I3. aarch64 `SYS_IOCTL` shadowing (fixed by the darshana bump)
darshana 0.9.0's bundle declared `var SYS_IOCTL = 16`, overriding the stdlib's arch-aware constant
program-wide: `cyrius build --aarch64` of agora 1.7.1 warned `duplicate symbol 'SYS_IOCTL' redefined
with conflicting value`, and 16 is `fremovexattr` on aarch64. Latent for agora (nothing it reaches issues
an ioctl). darshana ≥ 0.9.2 drops the local; the 1.8.0 aarch64 build is free of the warning, and
`cyrius test --aarch64 src/test.cyr` passes 225/225 under qemu.

### I4. Toolchain-surfaced warning in the vendored stdlib (not agora's)
cyrius 6.7.x reports `warning:lib/sigil.cyr:28103:12: array local over the per-fn frame budget gets
STATIC storage` (6.6.2 printed the same condition as a location-less `note:`). It is sigil's
`hash_file_into`, whose 256 KB `var buf[262144]` is deliberately static and banked per thread (its own
comment says so). agora never calls it (DCE NOPs it), and `lib/` is generated output that agora must
not edit. Recorded so it is not re-investigated; flagged to the owner at the 1.8.0 hand-off as a
cyrius/sigil item (every consumer of `sigil` now sees this warning).
